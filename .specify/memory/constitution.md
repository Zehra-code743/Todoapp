# The Evolution of Todo – Spec-Driven Cloud-Native AI System Constitution

## Core Principles

### I. Specification as Single Source of Truth

Specifications are the authoritative definition of system behavior and requirements. Code is a derived artifact generated from specifications. When system behavior deviates from requirements, the specification MUST be refined and code regenerated—never the reverse.

**Rationale**: This inverts the traditional code-first paradigm to enable true declarative system design where intent drives implementation, not implementation artifacts constraining design evolution.

### II. AI-Driven Implementation

All implementation artifacts (code, configuration, infrastructure definitions) are generated by Claude Code acting as planner, implementer, refactorer, and validator. The human role is System Architect, responsible for specification authorship, refinement, and governance enforcement.

**Rationale**: Removes manual coding friction, ensures consistent adherence to specifications, and enables rapid iteration cycles where specification changes automatically propagate to implementation.

### III. Stateless Architecture by Default

All system components MUST be designed as stateless services. State persistence occurs exclusively through external systems: databases, Dapr state stores, or event streaming platforms (Kafka). In-memory state is prohibited except for transient request-scoped data.

**Rationale**: Enables horizontal scaling, fault tolerance, cloud-native deployment, and eliminates state synchronization complexity in distributed systems.

### IV. Separation of Concerns

Each system layer has explicit, non-overlapping responsibilities:
- **Specifications** define what the system must do (requirements, behavior, contracts)
- **CLAUDE.md** defines how AI agents implement specifications (patterns, constraints, execution rules)
- **AI Agents** execute implementation following CLAUDE.md guidance
- **Infrastructure** provides deployment capabilities (orchestration, observability, networking)

**Rationale**: Clear responsibility boundaries prevent specification pollution with implementation details, enable independent evolution of each layer, and maintain architectural clarity.

### V. Tool-Driven Agent Actions

AI agents MUST NOT mutate system state directly. All state-changing operations occur through well-defined tools: REST APIs, MCP (Model Context Protocol) tools, or Dapr building blocks. Agents decide what to do; tools execute the how.

**Rationale**: Creates auditable, deterministic, reproducible agent behavior; prevents uncontrolled state mutations; enables observability and safety guardrails.

### VI. MCP as Control Plane

All AI agent capabilities are exposed via Model Context Protocol (MCP) tools. MCP tools MUST be:
- **Stateless**: No internal state across invocations
- **Auditable**: All inputs, outputs, and side effects logged
- **Deterministic**: Same inputs produce same outputs

**Rationale**: Standardizes agent-system interaction, enables safety verification, provides observability into agent actions, and ensures reproducibility.

### VII. Transparent Specification Evolution

All specifications MUST reside in `/specs` directory. Specification history MUST be preserved in version control. Judges and auditors may review specification evolution to understand design reasoning and iteration quality.

**Rationale**: Provides traceability of design decisions, enables learning from specification refinement patterns, and demonstrates deliberate architectural thinking over ad-hoc changes.

## Absolute Development Rules (Hard Constraints)

### No Manual Coding Rule 🚫

**Prohibited**:
- Handwritten code files
- Manual editing of AI-generated source files
- Direct bug fixes in implementation files

**Permitted**:
- Writing and refining specifications (Markdown)
- Writing CLAUDE.md guidance files
- Re-executing Claude Code after specification updates

**Enforcement**: When code behavior is incorrect → Update specification → Regenerate implementation

**Rationale**: Maintains specification-implementation consistency, prevents specification drift, and ensures all behavior is traceable to explicit requirements.

### Specification Before Implementation Rule

For every feature, the following artifacts MUST exist before code generation:
- Feature specification in Markdown format (`/specs/<feature>/spec.md`)
- Acceptance criteria with testable scenarios
- Clear definition of user-observable behavior

Claude Code MUST be instructed using:
- `@specs/...` file references to provide specification context
- Relevant CLAUDE.md sections for implementation guidance

**Rationale**: Prevents premature implementation, ensures shared understanding of requirements, and provides clear success criteria before resource investment.

### Transparent Spec History Rule

All specifications MUST:
- Live inside `/specs` directory structure
- Preserve iteration history through version control
- Include rationale for significant changes

Judges may review specification evolution to assess:
- Quality of requirements refinement
- Architectural decision reasoning
- Iteration effectiveness

**Rationale**: Creates accountability for design decisions, enables pattern recognition in specification quality, and demonstrates disciplined architectural thinking.

## Architecture Governance

### Stateless Systems by Default

Servers and services MUST NOT rely on in-memory state for business logic or data persistence.

**State Persistence Mechanisms**:
- Relational or NoSQL databases
- Dapr state stores (Redis, Cosmos DB, etc.)
- Event streaming systems (Kafka, NATS, etc.)

**Benefits**:
- Horizontal scaling without state synchronization
- Fault tolerance through stateless replica replacement
- Cloud-native deployment readiness
- Simplified disaster recovery

**Rationale**: Modern cloud architectures demand elasticity and resilience that stateful services inherently prevent.

### Separation of Concerns

**Layer Responsibilities**:

| Layer | Responsibility | Outputs |
|-------|---------------|---------|
| Specifications | Define what system must do | Requirements, behavior contracts, acceptance criteria |
| CLAUDE.md | Define how agents implement | Patterns, constraints, execution rules |
| AI Agents | Execute implementation | Code, configuration, infrastructure definitions |
| Infrastructure | Provide deployment capabilities | Orchestration, observability, networking |

**Prohibited**:
- Implementation details in specifications (e.g., "use Redis for caching")
- Business requirements in CLAUDE.md (agents follow "how", not "what")
- Direct state mutation by agents (must use tools)

**Rationale**: Prevents layer coupling, enables independent evolution, and maintains clear architectural boundaries.

## AI Agent Governance

### Agents Are Tool-Driven

AI agents MUST NOT mutate system state directly. All state-changing operations occur through:
- **REST APIs**: For service-to-service communication
- **MCP Tools**: For agent-specific operations
- **Dapr Building Blocks**: For infrastructure concerns (state, pub/sub, bindings)

**Agent Role**: Decide what action to take based on context
**Tool Role**: Execute the action with proper authorization, validation, and auditing

**Rationale**: Creates clear separation between decision-making (agent) and execution (tool), enabling safety verification and preventing uncontrolled mutations.

### MCP Is the Control Plane

All AI agent actions MUST be exposed via Model Context Protocol (MCP) tools.

**MCP Tool Requirements**:
- **Stateless**: No internal state preserved across invocations
- **Auditable**: All inputs, outputs, and side effects logged with context
- **Deterministic**: Same inputs produce same outputs (for given external state)

**Benefits**:
- Safety: All agent actions go through verified tools
- Observability: Complete audit trail of agent decisions and actions
- Reproducibility: Agent behavior can be replayed and verified

**Rationale**: Standardizes agent-system interaction, enables safety guardrails, and provides full observability into AI-driven operations.

## Cloud-Native Principles

This project follows Cloud-Native Architecture principles defined by the Cloud Native Computing Foundation (CNCF):

**Core Tenets**:
- **Containers over VMs**: All services packaged as container images
- **Kubernetes over single servers**: Orchestration-first deployment model
- **Event-driven over synchronous coupling**: Asynchronous communication via events where appropriate
- **Infrastructure as Specifications**: Infrastructure defined in code (Kubernetes manifests, Helm charts, Terraform)

**Rationale**: Aligns with industry best practices for scalable, resilient, portable cloud applications; ensures compatibility with modern deployment platforms.

## Governance

### Constitution Authority

This constitution supersedes all other development practices, coding standards, and implementation guidelines. Any conflict between this constitution and other artifacts MUST be resolved in favor of the constitution.

### Amendment Process

Constitution amendments require:
1. **Documentation**: Proposed change with rationale and impact analysis
2. **Approval**: Explicit consent from project architect
3. **Migration Plan**: Steps to bring existing artifacts into compliance
4. **Version Increment**: Following semantic versioning rules (see below)

### Version Semantics

- **MAJOR (X.0.0)**: Backward-incompatible governance changes, principle removals, or redefinitions
- **MINOR (0.X.0)**: New principles, sections, or material expansions of guidance
- **PATCH (0.0.X)**: Clarifications, wording improvements, typo fixes, non-semantic refinements

### Compliance Enforcement

All pull requests and design reviews MUST verify:
- Specifications exist before implementation
- No manual code modifications to generated files
- Agent actions use tools (no direct state mutation)
- State persistence uses approved external systems
- Complexity is justified when unavoidable

### Runtime Development Guidance

For detailed agent execution rules, implementation patterns, and workflow definitions, see `CLAUDE.md` in the repository root. CLAUDE.md provides operational guidance that MUST comply with this constitution.
