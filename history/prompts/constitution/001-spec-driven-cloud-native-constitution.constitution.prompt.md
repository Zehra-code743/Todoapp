## Prompt

The Evolution of Todo – Spec-Driven Cloud-Native AI System

1. Purpose of This Constitution

This constitution defines the non-negotiable principles, development rules, and governance model for this project.

The goal of this project is not to write code manually, but to design, specify, and govern intelligent systems using Spec-Driven Development and AI agents.

This document is the highest authority in the repository.
All specifications, implementations, and AI-generated outputs must comply with it.

2. Core Philosophy
2.1 Spec-Driven Development First

Specifications are the single source of truth

Code is a by-product of specifications

If behavior is wrong, the spec is refined, not the code

We change specs, not implementations.

2.2 AI as the Implementation Engine

All implementation is generated by Claude Code

The human role is System Architect, not coder

Claude Code acts as:

Planner

Implementer

Refactorer

Validator

3. Absolute Development Rules (Hard Constraints)
3.1 No Manual Coding Rule 🚫

❌ No handwritten code

❌ No editing generated files manually

❌ No fixing bugs directly in source files

✅ Allowed:

Writing and refining specifications

Writing CLAUDE.md guidance files

Re-running Claude Code after spec updates

If code is incorrect → Update the spec and regenerate

3.2 Specification Before Implementation Rule

For every feature, the following must exist before code generation:

Feature specification (Markdown)

Acceptance criteria

Clear user behavior definition

Claude Code must always be instructed using:

@specs/... references

Relevant CLAUDE.md context

3.3 Transparent Spec History

All specs must live inside /specs

Iterations are preserved (history matters)

Judges may review how specs evolved over time

4. Architecture Governance
4.1 Stateless Systems by Default

Servers must not rely on in-memory state

State is persisted via:

Database

Dapr state store

Event systems (Kafka)

This enables:

Horizontal scaling

Fault tolerance

Cloud-native readiness

4.2 Separation of Concerns

Each layer has a clear responsibility:

Specs → Define what

CLAUDE.md → Define how

AI Agents → Execute implementation

Infrastructure → Deploy capabilities

5. AI Agent Governance
5.1 Agents Are Tool-Driven

AI agents must not mutate state directly

All state changes happen via:

REST APIs

MCP tools

Dapr building blocks

Agents:

Decide what to do

Tools decide how it happens

5.2 MCP Is the Control Plane

All AI actions are exposed via MCP tools

MCP tools are:

Stateless

Auditable

Deterministic

This ensures:

Safety

Observability

Reproducibility

6. Cloud-Native Principles

This project follows Cloud-Native Architecture principles:

Containers over VMs

Kubernetes over single servers

Event-driven over synchronous coupling

Infrastructure as Specifications

7. Evaluation Alignment

This constitution is aligned with Hackathon evaluation criteria:

Judges will prioritize:

Spec clarity

Architectural decisions

AI governance

Reusability

Cloud-native readiness
